# ADR-020-FILE_UPLOADS

## Status
Accepted (2026-10-06) by the product owner. Closes OQ-14. Amends one rule of ADR-014 (upload path), see §3.

## Context
- `architecture/SECURITY_ARCHITECTURE.md`: "safe file uploads".
- `finance/EXPENSE_MANAGEMENT.md`: "Evidence attachments follow file security rules."
- `modules/organisation/ORGANISATION_PROFILE.md`: logo and cover are public profile fields.
- ADR-014: S3 API, private by default, public assets separated, server-side content-type allow-list, size limit and server-generated names, pre-signed URLs after server-side checks.

Product-owner answer (2026-10-06): images 2 MB, receipts 5 MB, type checked by content, no malware scanning in MVP (planned for Phase 12).

## Decision

### 1. Rules
| Use | Allowed types | Max size | Storage | Who |
|---|---|---|---|---|
| Organisation logo, cover | JPEG, PNG, WebP | 2 MB | public prefix `public/org/{organisationId}/…` | `organisation.update` |
| Expense evidence | JPEG, PNG, WebP, PDF | 5 MB | private prefix `org/{organisationId}/finance/…` | upload: the expense's creator holding `finance.expense.create`, DRAFT only; download: `finance.read` |

- The type is decided by the file's leading bytes (magic numbers). The client's filename and `Content-Type` are not trusted. Anything else is rejected with `415 UNSUPPORTED_FILE_TYPE`, and oversize files with `413 FILE_TOO_LARGE`.
- Object keys are generated by the server (`…/{uuid}.{ext}` from the detected type), never from client input.
- At most 5 evidence files per expense.
- No malware scanning in MVP. Phase 12 adds it before production (tracked as a Phase 12 item).

### 2. Serving
- Public assets are served from the public prefix (public bucket or CDN base URL from configuration).
- Private files are downloaded only through a pre-signed GET URL valid for 5 minutes, issued after the permission, entitlement and tenant checks. It is served with `Content-Disposition: attachment`, so it is never rendered as HTML from the application origin.

### 3. Amendment to ADR-014: uploads go through the API
ADR-014 says uploads use pre-signed URLs. A pre-signed PUT cannot enforce a size limit or inspect content, and the product owner required content checks. So uploads are sent to the API as the raw request body (size capped while streaming), checked, then written to S3 by the server. Downloads still use pre-signed URLs as ADR-014 says. All other ADR-014 rules are unchanged.

### 4. Storage module
One small module (`backend/src/storage.ts`) wraps the AWS S3 SDK, configured by `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_PUBLIC_BASE_URL`. Tests run against an in-process S3 emulator.

## Consequence
Phase 05 uses it for logo/cover, Phase 08 for expense evidence. SEC-007 and FIN-005 are verified against §1.
